## Implementation integrity verdict

**Pass.** The build expresses one product-specific system and says so in its
own terms. Every figure is a numbered plate with the same apparatus, the three
colour layers hold (the accent carries no datum, no register hue colours a
control, the ochre mark is the single warm thing), and the components that
exist are the ones the study needs — the unit field, the plate, the KWIC axis,
the scope band. The mechanical detector finds nothing. Nothing on the page is
interchangeable with an unrelated product: the wordmark's `<mark>`, the
Courier Prime reserved for `S/PV.####`, and the "what it does not show" note
under every figure are all claims this project alone makes.

## Findings

### [P2] A mark's register is carried by hue alone

- **Location**: `web/src/routes/reader/[meeting]/+page.svelte:586-594`, and
  `web/src/app.css:334-352` where the six underlines are declared.
- **Category**: Accessibility.
- **Impact**: A marked word carries its register as a 2 px underline in the
  register's colour. Which term was found is in the mark's `title`; which
  register it belongs to is not. The key above the record ("Highlights in this
  record") names each register beside its swatch, so the information is on the
  page — but for one mark in the middle of a speech, hue is the only thing
  that distinguishes legal from preventive. Two of the six hues are close
  enough that a reader with a colour vision deficiency would have to go back to
  the key for every mark.
- **WCAG**: 1.4.1 Use of Colour (A) — arguable rather than clear-cut, because
  the key is present and the mark itself is coded by the ochre wash.
- **Recommendation**: Give the underline a second code — a stroke pattern per
  register, the way the Chronology's lines already cross hue with dash — or put
  the register in the mark's `title` beside the term. This is a design decision
  about the record's texture, not a mechanical fix, which is why this pass
  reports it rather than making it.
- **Suggested command**: `/impeccable adapt`, then `/impeccable polish`.

### [P2] The Reader's return path discards the reader's query

- **Location**: `web/src/routes/reader/[meeting]/+page.svelte:392`.
- **Category**: Implementation integrity.
- **Impact**: "Back to the concordance" returns to an unfiltered concordance.
  A reader who arrived from a filtered result set has to rebuild the filter.
  Recorded as deliberately open on 14 September; still open.
- **Recommendation**: Carry the arriving search back in the link.
- **Suggested command**: `/impeccable harden`.

### [P2] The Concordance's scope band governs nothing on that page

- **Location**: `web/src/lib/ScopeControl.svelte`, shown on
  `web/src/routes/concordance/+page.svelte`.
- **Category**: Implementation integrity.
- **Impact**: The reading set is set in the masthead and the concordance's own
  paragraph says the set does not restrict the results. A control that is
  visible and inert on the page a reader is looking at is the one place on the
  site where the interface makes a promise the page does not keep. Recorded as
  a product decision on 14 September.
- **Recommendation**: The author's call: either the band applies here, or it is
  not shown here.
- **Suggested command**: `/impeccable shape`.

### [P3] The exit index keeps seven destinations

- **Location**: `web/src/routes/+page.svelte`, the index under the Overview.
- **Category**: Implementation integrity.
- **Impact**: Seven equal destinations at the foot of the Overview is a menu,
  not a route. Frozen because the copy is frozen.
- **Suggested command**: `/impeccable distill`, only if the copy freeze lifts.

### [P3] The masthead is nine rows tall at 320 px

- **Location**: `web/src/routes/+layout.svelte`, the nav row.
- **Category**: Responsive.
- **Impact**: At 320 px the section links wrap to four rows and the masthead
  takes 243 px before the page begins. Nothing overflows and every target is
  40 px, so this is a density question rather than a defect; at 390 px it is
  three rows.
- **Suggested command**: `/impeccable adapt`.

## Evidence

### Performance, measured

Same Playwright profile as `web/scripts/profile-payload.mjs`: Chromium,
service workers blocked, cache disabled, 1440 × 1000, unthrottled, built
site served by `vite preview`. The two builds differ only in
`CountryMap.svelte`.

| /actors, at rest before the map plate is reached | before | after |
|---|---|---|
| Transfer, total | 600.5 kB | 201.2 kB |
| Transfer, script | 480.0 kB | 90.9 kB |
| Transfer, stylesheet | 20.3 kB | 10.1 kB |
| Requests | 39 | 32 |
| Table ready | 374 ms | 416 ms |

On the constrained profile the same script uses (1.6 Mbps), the 399 kB that no
longer arrives before the map is reached is about two seconds of transfer.
Reaching the map costs it back, and only then.

Unchanged, as expected, because nothing on those paths was touched: Overview
LCP 232 ms → 184 ms, concordance filter interaction 70/50/50 ms → 81/49/50 ms.
Both are inside their "good" thresholds on an unthrottled profile and the
difference between the runs is noise.

### Responsive, measured

Every route walked at 320, 390, 720 and 1440 CSS px, counting elements whose
right edge passes the document's client width and that sit inside no scroll
container. 320 px is WCAG 2.2 SC 1.4.10's reflow width and stands in for 400 %
zoom; 720 px stands in for 200 % zoom at 1440.

| Route | 320 before | 320 after |
|---|---|---|
| Overview, Chronology, Words in context, Actors, Concordance, Reader | page scrolls to 367 px | none |
| Usage | page scrolls to 454 px | none |
| Semantic map, Methods | none | none |

Three causes, all fixed: the reading set's three cells could not fit one line
(now a column below 30 rem); a `<select>` in a control bar was as wide as its
longest option and the bar could not shrink it; and the referent list on Usage
carried a `table-scroll` class that no rule in that file defined.

### Accessibility, measured

- Every control (button, select, input, summary) is at least 24 px on both the
  Overview and Methods. The masthead's section links are 40 px each. The
  September finding of a 18.6 px `Methods` link, a 22.9 px disclosure summary
  and a ~22 px theme toggle does not reproduce.
- 87 targets are under 24 px in one dimension on the Overview. Every one is a
  link inside a sentence, a table cell or a figure caption, and none sits
  within 3 px of another target; the nearest neighbour of the provenance link
  is 36 px away. They pass 2.5.8 by its inline and spacing exceptions.
- Forced colours is handled explicitly for the first time, on eight surfaces:
  the masthead's current section and the contents band's current entry (both
  marked by an inset shadow, which is not painted in that mode, now restated as
  an underline that costs no height), the segmented group's and the scope
  band's pressed cell and the concordance's chosen delegation (all now the
  system's `Highlight` pair), the unit field's counted squares and their key
  (now `CanvasText`), a marked word's register rule, the concordance's
  query-hit rule and the Usage page's contested-reading rule (all now borders).
  Nothing opts out with `forced-color-adjust`, including the figures.
- `prefers-reduced-motion` is honoured in eight component-scoped places rather
  than by the global `0.01ms` kill the baseline flagged.
- The one custom widget, `SearchSelect`, is a correct combobox: `aria-expanded`,
  `aria-controls`, `aria-activedescendant`, `role="listbox"`/`option`,
  `aria-selected`, Escape and arrow handling, `mousedown` prevented so blur
  cannot eat the click, and a `role="status"` empty state.

### Theming, measured

Every colour in `web/src/**` resolves through a token. The only literals are
the fallbacks in `theme.ts` (deliberate: they are the second argument to a
`getComputedStyle` read that must hand ECharts a literal) and `#000` in
`UnitField`'s print rule. The semantic map's nine hard-coded hexes are gone.

### Integrity, measured

`node scripts/detect.mjs --json web/src` returns `[]`, subject to the coverage
caveat at the head of this report. `--paper-2` is undefined nowhere. The three remaining `var(--reg-*)` uses outside a figure's
marks are a chart stroke (`DiffusionChart`), a bar behind a keyness row
(`SpeakerKeyness`) and the reader's register swatches — all data, so the
quarantine holds.

## Positive findings

- The fetch boundary turns every failure into a sentence a reader can act on,
  and now tells a dead connection (offline, or a file the service worker never
  cached) from a file this release does not carry — the two recoveries differ.
  One exported sentence, used by the cache and by the semantic map's own fetch.
- Data tables under every figure mean the site degrades honestly: whatever a
  chart's colours do under an unusual display mode, the numbers are a
  disclosure away.
- ECharts is registered per module and split per route; four chart types and
  six components, not the whole library.
- The map's absence is designed for. Blocked basemap, lost WebGL context, a
  render loop that never runs in a background tab — each has its own status
  line, and each says the table above holds the same rows in the same order.

## Addendum, 19 September: what the Phase 6.6 critiques added

Three dual-agent critiques (Overview, Chronology, Concordance + Reader) ran
after this audit and found defects it did not. They are recorded in full under
`.impeccable/critique/`; the ones that change this report's picture:

- **Accessibility.** Two measured failures this audit missed, both now fixed:
  the standfirst's `<mark>` at 4.14:1 in the dark theme, and the concordance's
  query-hit rule at 3.14:1 on paper and 2.80:1 on the zebra row. Two that remain
  open: the calendar heatmap's labels render at **2.52 CSS px** at 390px (P0),
  and within a register shelf the chart's lines are told apart by lightness at
  **1.56–2.69:1** with end labels replaced by a legend above 8 series (P1).
  Accessibility would score **2**, not 3, against those two.
- **Integrity.** A false published number on 9,464 pages — every speech in the
  corpus carries `language: "Unknown"`, read as a foreign language — and
  off-token ECharts palette strokes, one of them blue, serialised invisibly into
  every SVG download from the Chronology. Both fixed.
- **A stale suppression.** `.impeccable/config.json` carries an `ignoreValues`
  entry for rule `side-tab` on the Chronology whose stated reason (a 3px left
  border) no longer exists in that file.

This audit's score is left as it was written, because rewriting it after the
critiques would hide the fact that a five-dimension audit did not find what two
isolated reviewers did.
