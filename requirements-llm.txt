# The protocol client used by model annotation step 14, and by nothing else.
#
# Separate from `requirements.txt` for the same reason `requirements-cluster.txt`
# is separate: a step that does not run in CI and does not run in the deploy
# should not put a package into the environment that both of them install. CI
# installs `requirements.lock` only, so it never sees this file — which is what
# makes the lazy `import openai` inside `14_llm_annotate.py` an enforced
# discipline rather than a stylistic preference. `scripts/lib/llm.py`, where
# the analytical contract lives, imports nothing from here and is unit-tested
# on a machine that has never installed it.
#
# Not hash-pinned. Reproducing a run does not mean reinstalling this file: a run
# is a committed artefact under `model_annotations/`, and what identifies it is
# the model id, the prompt hash and the referent hash recorded in its manifest,
# none of which the client library version can change.
#
# Install in the locked annotation environment on the cluster:
#     python -m pip install -r requirements-llm.txt
#
# Range verified against PyPI on 3 September 2026; 3.7.0 was the current release.
# The package is used as a protocol client for the OpenAI-compatible Responses
# endpoint served by vLLM, not as a client for a hosted vendor. The major stays
# capped because 3.0 already moved the HTTP client once; the run manifest pins
# the server and weights that determine the analytical output.
openai>=3.6.0,<4
