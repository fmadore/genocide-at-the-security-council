# Repository review — 8 October 2026

A full pass over the repository in five parts: research practice, pipeline code,
speed and build, tests, and the website. Items already tracked in
[ROADMAP.md](ROADMAP.md) (RV1–RV32 and the six open items) are not repeated.
Nothing here has been changed in the code; this file is a list to choose from.
Accepted items can move into ROADMAP.md as RV33 onwards.

**State at the time of review.** `ruff check` is clean. 1,268 Python tests pass
(6 skip locally because GNU make is not installed on Windows); the slowest is the
end-to-end golden test at 31 s. 635 web unit tests pass, and `svelte-check` and
`lint` are clean. A full deploy that cannot reuse its cache takes about 24.5
minutes (deploy run 37827234106).

**Overall.** The project is in good shape. The pinning, provenance records,
caveats and statistics are better than most published computational-text
studies. The real risks are few: one public figure that names states on labels
nobody has checked yet, no frozen version that a citation can point to, a
handful of website bugs, and a deploy that is slow and publishes even when
tests fail.

## A. Research practice — decisions for you

**A1. "Who rejects the word" marks delegations as unusual on unchecked labels.**
The figure ranks delegations and flags some as statistically unusual by the
share of their mentions the model labelled `rejects`
(`web/src/routes/usage/+page.svelte:1215-1236`). The prompt's distancing rule
sends "allegations of genocide" to `rejects`
(`model_annotations/genocide/PROMPT.md:171-175`), and both `docs/PLAN.md:222-230`
and `docs/INSTRUMENT_V4_PROPOSAL.md:20-24` say that rule is wrong. The on-page
caveat is good, but downloaded CSVs name the model and run without saying
"unvalidated, partial" (`web/src/lib/export.ts:124-130`). This is the output most
likely to be quoted out of context. Options: show plain counts without the
"unusual" markers until the gold sample measures how often `rejects` is right;
add a status line to every model-derived download and image.

**A2. There is no frozen version a citation can point to.** The only git tag is
`semantic-2026-09-11` (a data file the build uses). `CITATION.cff` has no
version, date or DOI, and `docs/PLAN.md:291-299` defers "a DOI/archive and
citable tag". The site is rebuilt on every push and the footer
(`web/src/routes/+layout.svelte:226-246`) shows no version or date; the
`analysis_hash` the Methods page tells readers to keep appears only inside
downloaded files. Suggested: connect the repository to Zenodo and release
"v0.1 — unvalidated preview" with the derived tables and a zip of the built
site; show release, date and commit in the footer; save key pages to the
Internet Archive. In `CITATION.cff`, add the version and DOI once they exist,
list the models used (Qwen3.8-27B, Gemma 4 31B IT, the embedding model), and
correct the corpus year: v5.0 was released on 31 March 2026
(`config/dataset-pin.json`), but the file says 2023.

**A3. Settle the instrument and write the evaluation rules before coding
starts.** ROADMAP open item 1 (code the gold sample) comes before item 2
(review instrument v4), yet v4 splits `rejects`, and `CODEBOOK.md:282-285` says
any change after the pilot needs a new version. Kappa and PABAK are computed
(`scripts/lib/usage.py:890-950`), but nothing says what level of agreement or
model accuracy is good enough, or what happens to a figure that fails.
Suggested, as a dated one-page plan committed before coding: the agreement
statistics per field (Cohen's κ and Krippendorff's α, with intervals); the
thresholds (for example α ≥ 0.67 tentative, ≥ 0.80 firm); a rule for withdrawing
a category that fails; the adjudication procedure. Also: flag or drop the 59
passages already reviewed against Qwen's labels (`PLAN.md:182-189`), which are
not excluded from the sample the way the prompt examples are; add a rule that
coders do not use the public site while coding, since it shows a model label
for every passage; and update `CODEBOOK.md:300`, which still describes a
`disagreement` frame the sample no longer uses.

**A4. Limits the site does not state yet.** These need new wording, so they
wait on your decision about the copy freeze.
- For speakers who spoke French, Russian, Chinese, Arabic or Spanish,
  *genocide* in the record is a UN translator's choice. The Methods page says
  the transcripts include translations (`methods/+page.svelte:216-220`) but not
  what that means for ranking delegations. Checking about 20 high-stakes
  passages against the original-language records would measure it.
- Informal consultations are outside the record; this is said only in
  `PLAN.md:247-248`. 830 of 10,294 meeting records contain no speeches
  (`CORPUS.md:15-16`).
- Counts are minimums because of scanning errors, and nothing measures scanning
  quality per decade; the limitations list (`CORPUS.md:115-128`) leaves this
  out.
- The Methods page says the intervals ignore meeting clustering
  (`methods/+page.svelte:296-300`), while the Chronology now draws its band
  from resampling whole meetings (`chronology/+page.svelte:1104`). The two
  pages disagree.
- The keyness cut-off (G² ≥ 10.83, `scripts/lib/lexical.py:95`) is p < 0.001
  with no adjustment for testing every word. That is fine as a filter, but
  should be said.

**A5. Lexicon precision has never been measured.**
`annotations/lexicon/annotations.csv` holds only its header row, so no term has
a measured precision, and recall is not estimated.

**A6. Third-party files in `docs/reference/`.** `1906.10969v3.pdf` and `.txt` are
an arXiv paper; unless it carries a Creative Commons licence (worth checking on
its arXiv page), arXiv's standard licence lets only arXiv redistribute it.
`Codebook.pdf` belongs to the retired corpus. Neither is needed now, and
`LICENSE-DATA.md:13` puts all prose under `docs/` under CC BY 4.0, which sweeps
them in. Suggested: remove them and link to the originals. The project also has
two titles (`CITATION.cff:2` and `LICENSE-DATA.md:28`).

**A7. The published run's record says it is still running.**
`model_annotations/genocide/runs/2026-09-08-qwen-131k/manifest.json` has
`"status": "in_progress"`, `"completed": null`, and a `git_commit` ending in
`-dirty` (it ran from uncommitted code). The commit cannot be repaired after the
fact, but the status can be closed, or a note can record why it stays open.

**A8. The documentation reads like a lab notebook.** `PLAN.md` says "Updated
10 September 2026" but holds 24 September entries, calls itself "not a
chronological work log" while being one, and gives the gold sample as "0/199"
(`:25`) where everything else says 469 rows over 453 occurrences.
`VALIDATION.md` keeps retired-corpus figures behind one banner (`:75-78`).
`INSTRUMENT_V4_PROPOSAL.md` is in French although the team works in English.
There is no data sheet for the derived tables, no dictionary of their fields,
and no ethics note (speakers are public officials speaking in office; labels
about named states are interpretations). Suggested: a two-page "claims and
their status" guide for reviewers and collaborators, and a data sheet for the
occurrence table.

**A9. Single points of failure.**
- The Gemma retry dispatcher exists only on Festus
  (`/workdir/$USER/unsc/gemma-retry-782721.sh`). `/workdir` is purged after 60
  days without writes, and the last writes were on 24 September. Commit it.
- A deploy that misses its cache re-downloads the corpus from Dataverse, which
  already failed three deploys on a bot check in August (`deploy.yml:29-30`).
  A Zenodo deposit of the pinned corpus and derived tables would be a second
  source.
- `requirements-vllm.txt` pins vLLM and nothing else of the GPU software.
- There is one maintainer; a short "what to do if the rebuild breaks" note
  would help whoever comes next.

## B. Confirmed bugs

**B1. A failed data load shows only "Internal Error".** There is no
`web/src/hooks.client.ts` and no `+error.svelte`. Every route loads through
`+page.ts`/`+layout.ts`, `data.ts:727-774` throws plain `Error`s, and SvelteKit
replaces the message of any plain error with "Internal Error". So the offline,
404 and validator messages never reach the reader on page load, and the claims
in `service-worker.ts:157-159` and the web README are untrue for those routes.
Fix: a `handleError` hook that passes the message through, plus an end-to-end
test of a failed load. No new copy needed.

**B2. The reader loses its occurrence tools under a referent filter.**
`reader/[meeting]/+page.svelte:87-89` calls `filterConcordance` without the
referent map, so `concordance.ts:198` drops every line. A reader arriving from a
concordance filtered by referent loses quotation, basket, citation and
previous/next without any message. Fix: pass the map, or look the selected line
up by id.

**B3. A filtered concordance CSV leaves out the referent filter.**
`concordance/+page.svelte:500-511` lists the filters again by hand and omits
`referent`, while `filtersInForce` (`concordance.ts:579`) includes it. A
download then misstates how it was filtered. Fix: build the list from
`filtersInForce`.

**B4. Two open tabs overwrite each other's basket.** `basket.svelte.ts` saves the
whole basket and never listens for changes made in another tab; the last tab to
save wins.

**B5. Six steps record the wrong code in their manifests.** Steps 10, 18, 19, 20
and 21 hand-list the library files they depend on, and every list is shorter
than the real imports (e.g. `20_actor_year.py:20` leaves out `council`,
`entities` and `frames`; `18_lexical_robustness.py:114-116` leaves out the
tokenizer changed in RV3). `tools/lib_deps.py:55` already computes the exact
list. Fix: have `artifacts.provenance` record it itself.

**B6. Running step 15 directly refuses the published run.** Only the Makefile
reads `allow_partial_run.txt` (`Makefile:19-27`);
`model_runs.ALLOW_PARTIAL_RUN` is defined but never read. So
`python scripts/15_usage.py`, the command `scripts/README.md` gives, refuses
where `make` accepts.

**B7. An error message gives a command that no longer exists.**
`usage_refusals.py:431` says to resume with `14_llm_annotate.py --poll`; the flag
is gone.

**B8. The same data comes out as different bytes on Windows and Linux.** Steps
18, 19 and 20 write CSV with the system's line ending; the local
`actor_year.csv` has 55,933 Windows line endings, the deploy writes none. Step 18
also writes parquet with a different compression from every other step. Fix:
one shared CSV writer that always uses `\n`.

**B9. A test that cannot fail.** `tests/test_end_to_end.py:226` ends in
`... or True`, so the "nothing leaked into the repository" check never runs.

**B10. `make clean` deletes things the build cannot recreate.** It removes all of
`data/derived` and `data/interim` (`Makefile:162`), including the GPU-only
embeddings (218 MB) and lemmas (160 MB), `llm_raw` (112 MB) and the verified
Gemma backup of 7 October. Fix: limit it to what `make payload` writes.

**B11. `submit_annotate.sh` blocks its own documented fix.** Its
`#SBATCH --mem=96G` (line 14) makes sbatch reject the `--mem-per-gpu` setting
that `docs/CLUSTER.md:356-367` says is needed to get scheduled. Fix: use
`#SBATCH --mem-per-gpu`.

**B12. A push that fails the tests still deploys.** `deploy.yml` does not wait
for the Checks workflow.

## C. Speed

**C1. Step 12 is 40% of a full build (9 min 49 s in CI).**
`lexical.matched_control` regroups all 167k speeches for every speaker pairing
(`scripts/lib/lexical.py:513-515`), and `keyness.strata` joins keys row by row
(`keyness.py:264`). Grouping once and keeping the candidate order would bring it
to an estimated 2–3 minutes with identical output; the existing pairing test
checks that.

**C2. Step 03 takes 6 min 34 s.** Speech text is held as plain Python objects
(`scripts/lib/frames.py:62`), which makes each of 49 case-insensitive scans
about 15 times slower than Arrow strings (measured). `check_widenings` searches
every speech without the prefilter (`lexicon.py:846-856`), and `ocr_delta`
recounts terms already counted (`lexicon.py:799-801`). Estimated result: about a
minute. The committed `lexicon.counts.json` already proves whether counts move.

**C3. The deploy cache is thrown away for edits that change nothing.** Of the
last 77 deploys, 6 rebuilt everything (about two hours of runner time) for
edits to cluster scripts, step 14 or `scripts/README.md`, because the cache key
hashes all of `scripts/**`. Fix: key it on the Makefile's real prerequisites,
or exclude `scripts/cluster/**`, `scripts/**/*.md`, step 14 and the probe and
preflight scripts.

**C4. The build runs one step at a time.** `make -j3 payload` would take about
17.5 minutes now and about 5 after C1 and C2 (estimate). Also set
`PYTHONUNBUFFERED=1` so the CI log shows where time goes inside a step.

**C5. The same work is repeated across steps.** Six steps rebuild the list of
matches (03, 08, 09, 13, 15, 17; 13 and 15 scan all speeches with no
prefilter). Step 05 re-tokenizes about 8,000 speeches on each of 21 repetitions
(`05_lexical.py:334-337`) and step 12 tokenizes the corpus again. One shared
occurrences table and one shared word-count table would remove this. Larger job.

**C6. Step 04 reads all 111 columns, text included** (`04_series.py:1003`), and
never uses the text.

**C7. The concordance sort takes seconds.** The comparator recomputes its keys on
every comparison (`concordance.ts:207-218`): 1.6 s for *genocide* and 3.0 s for
*impunity*, against 85 ms and 143 ms with keys computed once (measured). It runs
on every filter change and every previous/next click in the reader.

**C8. The chart library is not lazy-loaded.** ECharts (650 KB) is imported at
the top of `Chart.svelte`, so it loads before Overview, Chronology and Language
can respond, and two modules it registers (graph series, mark lines) are never
used. The web README says it is lazy.

**C9. Data downloaded but not needed.** The concordance's referent filter fetches
`usage/occurrences.json` (6.9 MB) to build a map that would be 0.27 MB
(`concordance/+page.svelte:354`). `frames/occurrences.json` (1.36 MB) is shipped
and never fetched. No size budget is enforced anywhere; `profile-payload.mjs`
runs only by hand.

**C10. Browser caching has no limit.** The service worker keeps every data file
it has ever fetched until the next deploy (`service-worker.ts:133-140`), and
`preload-data="hover"` on the whole page (`app.html:53`) fetches 3.4 MB when the
pointer passes over the Actors link. The in-memory cache in `data.ts` also
makes prerendered pages inline their data inconsistently (Chronology inlines 3
of 8 files).

## D. Code structure

**D1. One decision, several copies.** The matched-control strata `MATCH_ON` is
defined three times (`05_lexical.py:142`, `18:23`, `lib/keyness.py:56`); the
seed `20_260_807` four times (05, 12, 18, 19). Paths are defined separately by
the step that writes a file and the one that reads it: gold files (13, 15,
`tools/coding_page.py`), `referents.csv` (03, 13, `model_runs.py`), the
semantic directory (21, `export_web`, `fetch_semantic`), `actor_year` (20,
`export_web`). Move each to one place (`paths.py`, `lexical.py`).

**D2. `referents.csv` has four parsers with different rules**
(`audit.py:684`, `audit.py:749`, `llm.py:491`, `15_usage.py:166`). Step 15's
version accepts fewer headers and gives a traceback on a bad version cell. One
`lib/referents.py` would replace them.

**D3. Where to split the largest modules.** Do it in steps with byte-identical
outputs, as RV29 did.
- `lib/usage.py` (2,170 lines): agreement statistics (868–1323) to
  `agreement.py`; gold-sample estimation (1325–1831) to `gold_estimates.py`;
  the two-run comparison (1833–2123) to `usage_comparison.py`.
- `lib/llm.py` (1,650): prompts (251–475), evidence location (1087–1313), and
  the run-file functions (1560 onwards), which belong in `model_runs.py`. The
  run store is still split across four modules, which RV23 meant to end.
- `lib/topics.py`: projection diagnostics (857–1388), since step 21 depends on
  them while the module calls itself evaluation-only.
- `lib/audit.py`: schema vocabulary (1–250) and sampling (279–590).
- Step 04's payload builders (102–683) belong in `lib/series`; steps 04, 07, 11
  and 15 each hand-write Markdown tables for their notes.

**D4. Library code ends the process.** `console.fail` always exits but is typed
as returning normally (`console.py:39`), so two callers add an unreachable
`raise`. Some `lib` modules exit, others raise errors. First step: type it
`NoReturn`. Later: `lib` raises one error type, and each script turns it into
an exit.

**D5. Dead code.** Never used: `annotate.BATCH_CHUNK`,
`audit.LEGACY_ANNOTATION_FIELDS`, `console.timed`, `model_runs.PROMPTS`,
`paths.DOCS`. Used only by tests since the corpus migration:
`actors.crosswalk_drift`, `council.validate_against_corpus`.
`tools/split_intrusion_task.py` is a one-off migration already applied.

**D6. A type checker would be cheap to add.** There are 26
`# type: ignore[...]` comments with mypy codes but no mypy run, so nobody knows
whether they are still needed. 94% of functions are already annotated. Start
with `scripts/lib`.

**D7. History in comments — your call.** Comments that explain why a value is
what it is age well. The 45 that record what the code used to be go stale: the
`pyproject.toml` note says the `sys.path` header has "fifteen copies"; there are
33. The `tsconfig.json` note says TypeScript "stays on 5.x"; `package.json` has
6. Keeping the reasons and moving the history into commit messages would stop
that.

**D8. Website routes.** The seven large routes total 10,600 lines. The URL-sync
pattern is copied in five routes; nine effects reset state when another value
changes, which is why a `tick()` workaround exists; loading and retry handling
is written by hand four times; twenty CSV builders sit inside components and
`toCsv` (`export.ts:146`) never checks that a row has as many cells as there are
columns. Untested logic still in components: usage `instrumentReferents`,
language `matrixTerms`/`alignedRows`/`compareTop`, reader `segments`/`visible`,
overview `totals`/`densest`/`loudest`.

**D9. Website tooling.** `noUncheckedIndexedAccess` is off, although
`chronology/+page.svelte:489-501` documents a crash of exactly that kind. The
linter does not catch unawaited promises. Prerendering is only exercised by the
deploy, not by Checks. `chronology/+page.ts:27` turns every failure, including
validator refusals, into "no data". The payload size is given as 468 MB in the
README and `svelte.config.js` and as 675 MB in `service-worker.ts:12`.

## E. Tests

**E1. The new rate bands and decomposition are tested for shape only.** No test
calls `series.meeting_bootstrap` or `series.rate_decomposition`; the golden test
does not include them; `bandBounds` in `chronology.ts:235` has no test; the
browser fixtures do not carry the fields, so the clustered band is never drawn
in a test. Suggested: check that composition plus within-group change equals
the total exactly, one hand-worked example, and that the meeting bootstrap is
wider than Wilson when the word sits in a few meetings.

**E2. About 3,500 lines of step code never run under a test:** steps 01, 02, 03,
05, 09, 13, 15, 19 and 20. The end-to-end test covers 04, 08 and 17; 11, 12 and
15 refuse a small synthetic corpus because the expected totals are fixed in
`paths.py:133-147`. Making those totals overridable would let it cover 05 and
15.

**E3. Browser test gaps.** No test visits `/language` (1,736 lines) or
`/methods`, so neither gets an accessibility scan; all eight scans run in light
mode only; `DotPlot`, `FrameProfile` and `TermMatrix` are never rendered; only
the `scopes.json` fixture is checked against the payload contract, so the
hand-written fixtures can drift from what the pipeline writes.

**E4. The golden test compares 36 decimals exactly** (`test_end_to_end.py:221`),
across Linux CI and Windows ARM development. A tolerance of one part in a
billion would remove the risk of last-digit drift.

**E5. Statistics are checked against their own formula.** `test_lexical.py:117-124`
rebuilds the G² expression it tests; Wilson is checked only for general
properties. Pin both to published or independently computed values. Kappa, the
binomial tail and Benjamini–Hochberg already have hand-worked values. A
property-based test (the `hypothesis` library) that the count, the spans and
the concordance lines always agree would cover every term at once.

**E6. Tests that read source code instead of behaviour.**
`test_topics.py:776-882` and `test_cluster.py` (e.g. `:207`, `:233`, `:278`,
`:316`) search the text of scripts, including a comment, and break on harmless
edits. For the shell scripts, `bash -n` and shellcheck in CI would test more.

**E7. CI settings.** No coverage is reported. The `slow` marker is never used to
deselect anything. Adding `--strict-markers` and turning `FutureWarning` into an
error would catch pandas and numpy announcing changes that move numbers.
Playwright retries twice in CI without reporting flaky tests.

**E8. Eight separate fake-corpus builders** across the test files
(`test_actors.py:54`, `test_series.py:21`, …). A column renamed in step 02 would
leave all of them passing. One shared builder in `conftest.py`, checked against
the real column list, would not.

## F. Cluster scripts

- `fetch_results.sh --watch` opens a new ssh connection every 20 s (lines
  63–66); the cluster bans an address for about 10 minutes after rapid
  connections. Reuse one connection.
- `fetch_results.sh` cannot fetch model-annotation runs; that is done by hand.
- `push_code.sh` never deletes files on the cluster, so a deleted module stays
  importable there.
- `export VAR="$(cmd)"` at `submit_annotate.sh:82` hides a failing command from
  `set -e`.
- The Makefile needs GNU make 4.3 (`&:`, `$(file <)`); older versions misread it
  without an error. A version check would stop early.

## Already strong — keep doing

- The corpus is pinned by Dataverse file ids and checksums, checked before any
  network request; Python packages are locked with hashes; lexicon counts are
  committed and enforced.
- Each model run records weights, server, hardware, sampling settings and
  prompt hash; superseded prompts are archived; model output never enters the
  human annotations; agreement between models is described as stability, not
  accuracy.
- The gold-sample design: blinded packet, three sampling frames with weights
  back to the corpus, prompt examples excluded, double coding, adjudication
  kept separate.
- Downloads carry provenance headers, and single occurrences can be cited.
- The statistics: meeting-level permutation tests, Bonferroni and
  Benjamini–Hochberg corrections, the agenda-composition decomposition, matched
  comparison speeches.
- Automatic fixes are logged in `VALIDATION.md` rather than absorbed silently.
- The code: lint-clean, 94% of functions typed, no bare `except`, tests free of
  sleeps, unseeded randomness and network calls; Svelte 5 throughout with no
  legacy syntax and no raw HTML injection.
